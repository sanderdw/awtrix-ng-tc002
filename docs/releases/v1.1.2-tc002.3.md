## What's new in v1.1.2-tc002.3

- **Installs on more stock firmware** ([#8](https://github.com/sanderdw/awtrix-ng-tc002/issues/8),
  [#6](https://github.com/sanderdw/awtrix-ng-tc002/issues/6)). Every stock version ships a
  different Ulanzi application (`libzkgui.so`), and only the 1.1.1 build was recorded, so the
  installer refused clocks on 1.0.1, 1.0.8 or 1.1.3. The launcher only calls four functions in
  that application: the FlyThings app entry points and the SDK's `base::wifiOnAndWait`. The
  installer and the update helper now read the application's ELF symbol table (it is never
  loaded) and accept it when those four are there. The installer reports that as
  **compatible** instead of **verified**. The audio and network libraries still need an exact
  recorded build, because the port passes hand-measured structures to them.
- **`--allow-unverified` works.** It now passes `--force` to the update helper, which it never
  did, and it says which feature stays off (audio, or DHCP after the first lease, static
  addressing and the fallback access point) instead of a blanket warning. A stock application
  without the four entry points is refused even with the flag: without them, holding the knob or
  three failed starts could not bring the stock app back.
- **`--restore` always works.** It runs the helper with `--force`: the recovery image is the
  clock's own stock partition. It was refused on every clock that had been force-installed.
- The installer prints the full SHA-256 of anything it does not recognise, ready to paste into an
  issue. `/api/v1/tc002/vendor` gains `status` (`verified`, `compatible`, `unknown`) and the vendor
  application's `requiredSymbols` and `missingSymbols`.

**Installed an earlier release by running the helper with `--force`?** Take this update with
the one-line installer once, not the web UI. The web UI update runs the helper that is already
on the clock, which still refuses your stock application.

Host tests cover both symbol readers, including 500 damaged files on which they must agree.
Neither this build nor the new check has run on a clock yet, and the
[release validation protocol](https://github.com/sanderdw/awtrix-ng-tc002/blob/main/docs/VALIDATION.md)
has not been run on it, which is why it is a pre-release.
