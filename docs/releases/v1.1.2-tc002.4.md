## What's new in v1.1.2-tc002.4

- **Scripts send their own `Content-Type` once**
  ([#11](https://github.com/sanderdw/awtrix-ng-tc002/issues/11)). A Berry script that set
  `Content-Type` sent the header twice, and strict endpoints such as Spotify's token endpoint
  answered 400. The script's header now goes out unchanged. `application/octet-stream` is
  added only when a request has a body and no type, and a request without a body gets no
  `Content-Type`.
- **MP3s with cover art play; unplayable MP3s are refused at upload**
  ([#12](https://github.com/sanderdw/awtrix-ng-tc002/issues/12)). The decoder plays MPEG-1
  Layer III at 32, 44.1 or 48 kHz, as on the ESP32. Two kinds of file uploaded without complaint
  and then stopped with "MP3 decoding failed":
  - an MPEG-1 file with embedded cover art of more than about 128 KB. It now plays: playback
    skips the ID3v2 tag;
  - an MPEG-2 file, such as 22 or 24 kHz text-to-speech or a short sound effect, or an MP2
    file. The upload is now refused with the reason, for example *MPEG-2 audio at 22050 Hz is
    not supported; re-encode it as MPEG-1 Layer III at 32, 44.1 or 48 kHz*. A file that reaches
    the MP3 folder another way gets the same message when it plays.

Host tests cover the header building, and the MP3 check against MPEG-1, MPEG-2, MP2, oversized
tags and noise. On a clock, a RAM trial refused MPEG-2 and MP2 uploads with the reason and played
MPEG-1 files with and without 200 KB of cover art. In the same trial, a script's form POST
reached a server with one `Content-Type`. The
[release validation protocol](https://github.com/sanderdw/awtrix-ng-tc002/blob/main/docs/VALIDATION.md)
has not been run on it, which is why it is a pre-release.
